    The same generated answers scored by two different judge models. Large disagreements show how much LLM-as-a-judge scores depend on the judge.

    What is compared

    • BM25: keyword search (rank_bm25, identifier-aware tokenizer).
    • Vector: BAAI/bge-small-en-v1.5 embeddings + FAISS cosine search.
    • Hybrid: Reciprocal Rank Fusion of BM25 and vector rankings.
    • Agentic: a LangGraph state machine: route (pick bm25/vector/hybrid) → retrieve → grade (is the context sufficient?) → rewrite the query and retry, or finalize (fuse all attempts if none passed).

    Every pipeline uses the same chunks, top-k and answer prompt, so only retrieval differs.

    Metrics

    • Hit@k, MRR, nDCG@k: was the gold chunk (the passage each question was written from) retrieved, and how high.
    • Faithfulness: share of the answer's claims supported by the retrieved context (LLM judge).
    • Relevance / correctness: LLM-judge 1–5 scores rescaled to 0–1; correctness compares with a reference answer.
    • Latency / cost: wall-clock seconds and LLM calls per question.

    Setup

    Questions are LLM-generated from the docs (half keyword-style, half paraphrased) and should be treated as a pilot: with a small question set, a difference of one question is several points.
